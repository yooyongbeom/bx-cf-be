# BX-CF PostgreSQL DBMS 표준가이드 개정 설계

## 목적

기존 `ILIS-AN220-DBMS표준가이드.doc`의 문서 구조와 실무 가이드 성격을 유지하면서, SQL Server 중심 내용을 `bx-cf-be`의 PostgreSQL·JPA·MyBatis 개발 방식에 맞게 개정한다.

## 산출물

- 원본 DOC는 변경하지 않는다.
- 최종 개정본은 원본과 같은 폴더에 `ILIS-AN220-DBMS표준가이드-BX-CF.docx`로 저장한다.
- 변환본, PDF, 페이지 이미지, 점검 자료는 원본 폴더의 `_codex_tmp_dbms_guide`에서만 관리한다.
- 저장소의 애플리케이션 코드는 변경하지 않는다.

## 프로젝트 기준

- 런타임: Java 21, Spring Boot 3.3.4
- DBMS: PostgreSQL, JDBC 드라이버 `org.postgresql:postgresql`
- 데이터 접근: JPA와 MyBatis 병행
- 데이터베이스명: `bxcfdb`
- 실제 Mapper에서 사용하는 PostgreSQL 요소: `LIMIT`, `OFFSET`, `COALESCE`, `current_timestamp`, `jsonb`, `WITH RECURSIVE`, `NULLS FIRST`, `split_part`, `::integer`, `::text`
- 식별자 표준: 따옴표 없는 소문자 `snake_case`
- SQL 키워드 표기: 대문자
- 민감정보 제외: DB 호스트, 계정, 비밀번호는 문서에 기록하지 않는다.

## 개정 방식

기존 8개 장의 큰 흐름과 표·예제 중심의 표현을 유지하되, 프로젝트에 맞지 않는 부분은 국소적으로 대체한다. 표지, 개정 이력, 머리글·바닥글, 목차, PostgreSQL 관련 장과 SQL 예제를 우선 개정하고, 일반적인 관계형 모델링·정규화·ERD 설명은 의미를 보존하면서 용어·오탈자·데이터 타입만 보정한다.

## 장별 개정 범위

### 1. 개요

- ILIS 전용 문구를 BX-CF 백엔드의 데이터베이스 설계 및 서버 애플리케이션 개발 범위로 변경한다.
- JPA Entity, MyBatis Mapper XML, DDL, SQL, 인덱스, 데이터 타입을 적용 대상으로 명시한다.

### 2. 데이터 표준화 지침

- 표준단어·도메인 원칙은 유지한다.
- SQL Server식 `datetime`, 이름 있는 Default 제약조건, 빈 문자열 중심 기본값을 PostgreSQL 타입·제약조건 기준으로 교체한다.
- 대표 타입은 `bigint`, `integer`, `numeric(p,s)`, `varchar(n)`, `text`, `date`, `timestamp with time zone`, `boolean`, `jsonb`로 정리한다.
- 날짜/시간을 문자열로 저장하지 않고 의미에 맞는 날짜·시간 타입을 사용하도록 변경한다.
- `Y/N` 컬럼은 기존 프로젝트 호환을 위해 `char(1)`과 `CHECK` 제약조건 사용을 허용한다.

### 3. 물리 DB 설계 지침

- PK는 `GENERATED BY DEFAULT AS IDENTITY` 또는 업무키를 사용한다.
- 공유 환경의 스키마 변경은 승인된 DDL 또는 마이그레이션으로 수행하고 `ddl-auto` 자동 변경에 의존하지 않는다.
- PostgreSQL MVCC, 자동 통계, 복합 인덱스 선두 컬럼, 부분 인덱스, 표현식 인덱스, FK 인덱스 검토 기준을 반영한다.
- 성능 판단은 추측이 아니라 `EXPLAIN (ANALYZE, BUFFERS)`와 운영 통계를 근거로 한다.

### 4. 데이터베이스 객체 명명 규칙

- 데이터베이스명은 `bxcfdb`, 기본 스키마 예시는 `public`으로 기술한다.
- 테이블·컬럼·뷰·시퀀스·함수·프로시저·트리거·제약조건·인덱스는 소문자 `snake_case`를 사용한다.
- 따옴표로 대소문자를 강제하는 식별자는 금지한다.
- 기존 프로젝트의 복수형 테이블명(`users`, `roles`, `products`, `menus`, `common_codes`)을 예시로 사용한다.
- 시노님과 SQL Server 인라인 테이블 함수 항목은 PostgreSQL의 스키마·뷰·집합 반환 함수 설명으로 교체한다.
- 제약조건과 인덱스 예시는 `<table>_pk`, `<table>_<column>_uk`, `<table>_<column>_fk`, `<table>_<columns>_idx` 형식으로 통일한다.

### 5. 프로그래밍 규칙

- Mapper SQL은 `/* service.Mapper.method(설명) */` 형태의 식별 주석을 사용한다.
- 테이블·컬럼 별칭은 의미 있는 소문자로 작성한다.
- `#{...}` 바인딩을 사용하고 문자열 치환 `${...}`은 검증된 화이트리스트 외에는 사용하지 않는다.
- `SELECT *`를 피하고 필요한 컬럼을 명시한다.
- 페이지네이션은 결정적인 `ORDER BY`와 `LIMIT`·`OFFSET`을 함께 사용한다.
- 대량 페이지네이션은 필요 시 키셋 방식으로 전환한다.
- 트랜잭션은 JPA와 MyBatis의 해당 TransactionManager 경계를 명확히 하고 불필요하게 길게 유지하지 않는다.

### 6. SQL 일반

SQL Server 전용 구문을 다음 PostgreSQL 구문으로 교체한다.

| 기존 | PostgreSQL 개정 |
|---|---|
| `TOP n` | `LIMIT n` |
| `TOP n PERCENT` | 별도 집계 또는 윈도 함수 |
| `WITH(NOLOCK)` | 제거하고 MVCC·격리수준 설명 |
| `ISNULL(a, b)` | `COALESCE(a, b)` |
| `GETDATE()` | `current_timestamp` |
| 문자열 `+` | `CONCAT(...)` 또는 `||` |
| `CONVERT(...)` | `CAST(...)`, `to_char(...)` |
| `SELECT ... INTO new_table` | `CREATE TABLE ... AS SELECT ...` |
| SQL Server `IDENTITY` | `GENERATED BY DEFAULT AS IDENTITY` |

실제 프로젝트 패턴을 바탕으로 `jsonb` 캐스팅, 재귀 CTE, `NULLS FIRST`, 버전 문자열 처리, 안정적인 동적 정렬 예제를 추가한다.

### 7. DBMS 일반 / 8. ERD 기초

- 관계형 데이터베이스, 정규화, ERD, JOIN 설명은 유지한다.
- 예제 객체명은 소문자 `snake_case`로 변경한다.
- 날짜·시간·숫자 타입을 PostgreSQL 타입으로 보정한다.
- 구식 쉼표 조인은 제거하고 ANSI JOIN만 사용한다.
- 최종 학력 1건 조회 예제는 `ROW_NUMBER()` 또는 `LATERAL JOIN ... LIMIT 1`로 교체한다.

## 품질 및 검증

- 원본 문서의 페이지 구성, 표, 그림, 머리글·바닥글을 가능한 한 유지한다.
- 목차와 페이지 번호는 최종 문서 기준으로 갱신한다.
- 최종 텍스트에서 `WITH(NOLOCK)`, `TOP `, `ISNULL(`, `GETDATE(`, `CONVERT(`, `MS-SQL`, `ILIS` 잔존 여부를 검사한다. 문서번호가 포함된 원본 파일명 외에는 ILIS 표현을 남기지 않는다.
- 모든 SQL 예제의 PostgreSQL 문법과 용어를 점검한다.
- 최종 DOCX를 PDF와 페이지 PNG로 렌더링하고 모든 페이지에서 글자 잘림, 겹침, 표 파손, 누락 글꼴, 머리글·바닥글 오류를 검사한다.
- 렌더링 후 변경이 발생하면 다시 렌더링하여 재검사한다.
